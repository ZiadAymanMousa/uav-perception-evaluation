# Preparation: portable execution and defensible claims

Understand these distinctions before presenting this component or its results:

1. Original source content, the converted task and a particular generated manifest are different identities. Reviewed semantic equality allows a new equivalent preparation; exact launch byte hashes still protect an existing run and resume.
2. The trust anchor is the reviewed task configuration. Replacing expected hashes to make an error disappear changes the task rather than validating the original one.
3. Labels preserve float32 geometry and order, class order and explicit exclusions. Three exact malformed original rows are documented exceptions; ignored image pixels remain in the loss. This is the converted ten-class task, not native VisDrone scoring.
4. A historical checkpoint retains its original training record. Its smoke certificate records equivalent evaluation content and different manifest bytes. It never means new training occurred.
5. A CPU preflight checks input identity and source/config provenance. A one-image inference smoke checks runnable plumbing. Neither establishes a completed 150-epoch portable run, final-test performance, stable latency, clean installation or a scientific improvement.
6. Prospective development inference requires completed actual training evidence, including contiguous epoch histories and selected-checkpoint/config/source hashes. Resume uses exact bytes even when two preparations have equal semantics.
7. Saved-output scoring must keep the run's purpose and verify all pairs, logs and data. A smoke AP number must not become a research comparison or a new benchmark row.

The underlying study compares established full-frame resolution and fixed slicing on exposed validation. This component improves how another researcher could prepare and check that task. It does not add novelty to the detector, expand the validation population, establish independent human mastery or convert an unpublished package into peer review.

Before a future release, inspect the complete code/prose and recorded scope. Keep private operational paths, historical certificate, local datasets/weights, raw smoke outputs and test-attempt directories out of the public payload. Preserve licences and actual source attribution.
